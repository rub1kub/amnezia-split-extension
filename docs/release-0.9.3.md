Routeva 0.9.3 отделяет запросы управления Gateway от выбранного VPN-выхода.

- Домен Gateway идёт напрямую даже в режиме «Весь интернет». Выбор неработающего узла больше не должен мешать загрузке списка и проверке других узлов из-за маршрута внутри самого расширения.
- Проверка и получение состояния сначала используют стандартный HTTPS/443: `/routeva-api/v1/...`.
- Для старых установок автоматически сохраняется резервный API на 18445. Ошибка авторизации не маскируется переключением адресов, а изменение подписки или выбранного узла не повторяется после неоднозначного сетевого сбоя.
- Пользовательские адреса API с нестандартным портом или путём сохраняются. Пароли и VPN-ключи менять не требуется.

На сервере добавьте reverse proxy из `gateway/apache-api443.conf.example` в нужный HTTPS VirtualHost, заменив имя backend. Сохраните старый API. Для www-домена исключите `/routeva-api/` из перенаправления на основной домен. Backend TLS проверяется по имени и цепочке доверия; отключать проверку сертификата не требуется.

Распакованное расширение нужно один раз перезагрузить на карточке Routeva в `brave://extensions` / `chrome://extensions`. После этого проверьте «EU Авто» с выключенным внешним VPN. Если сам адрес Gateway заблокирован, прямой маршрут расширения не снимает такую блокировку.

Проверено: 50 JavaScript-тестов и 23 Python-теста. Оба аккаунта получили успешный пинг через HTTPS/443 с физического Ethernet-интерфейса Windows без локального прокси Happ. Проверка в основном окне Brave не выполнена из-за остановки автоматического управления браузером.
