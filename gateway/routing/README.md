# Общие правила прямого доступа

Routeva 0.9.2 направляет российские домены и IP-диапазоны напрямую, включая режим «Весь интернет». Правила обхода имеют приоритет над списком VPN. Домены проверяются по точному имени/суффиксу, IPv4 — бинарным поиском по интервалам; для IPv6 поддерживаются литералы адресов. Определение страны произвольного IPv6-адреса домена через PAC DNS не поддерживается: для таких соединений используются доменные правила.

Список категорий российских сервисов берётся из MetaCubeX/meta-rules-dat (category-ru, исходные данные v2fly/domain-list-community), IPv4/IPv6 — из IPdeny. Это классификация по спискам, а не гарантия определения каждого российского сервиса или географического положения сервера. Общие CDN и новые домены могут требовать уточнения списка.

## Сервер

Нужны Linux, systemd, Python 3.10+, `getent` и HTTPS-сайт на том же имени, которое введено как адрес прокси. Порты API и прокси не меняются; публичные файлы выдаются через стандартный HTTPS/443. Данные публичны и не содержат VPN-ключей, паролей или ссылок подписок.

Из корня репозитория, с правами root:

```sh
useradd --system --home-dir /var/lib/routeva-rules --shell /usr/sbin/nologin routeva-rules
install -d -m 755 -o routeva-rules -g routeva-rules /var/lib/routeva-rules
install -d -m 755 /usr/local/lib/routeva-rules
install -m 644 gateway/routing/update_ru_routing.py /usr/local/lib/routeva-rules/
install -d -m 755 /usr/local/lib/routeva-rules/licenses
install -m 644 data/licenses/* /usr/local/lib/routeva-rules/licenses/
install -m 644 gateway/routing/routeva-rules-update.service gateway/routing/routeva-rules-update.timer /etc/systemd/system/
systemctl daemon-reload
systemctl start routeva-rules-update.service
systemctl enable --now routeva-rules-update.timer
```

Если пользователь уже существует, повторный `useradd` пропускается. Добавьте содержимое `apache-routing.conf.example` в нужный HTTPS VirtualHost перед общим обработчиком `/`, проверьте `apache2ctl configtest`, затем выполните `systemctl reload apache2`. Для Nginx нужен аналогичный статический alias. Не публикуйте `/etc/routeva-gateway` или каталог пользовательских VPN-профилей.

Проверьте `https://ваш-домен/routing/status.json` и `/routing/ru-direct.json`: оба должны отдавать HTTP 200. Дождитесь окончания первой сборки (до пяти минут). Если домен прокси перенаправляет на основной HTTPS-сайт, путь `/routing/` должен сохраняться. Сервер обновляется ежедневно в 04:15–04:45 по Москве, Routeva проверяет данные при запуске и каждые шесть часов. Ручная проверка доступна в настройках расширения.

До завершения загрузки и валидации прежняя версия не меняется. Новый комплект публикуется атомарной заменой ссылки `current`. При сетевой ошибке, повреждённом ответе, слишком широком диапазоне или резком сокращении списка остаётся прежний комплект. В расширение включена начальная копия: она работает и при недоступности сервера. Число пропущенных сервером DNS-ответов видно в `resolvedDomains`.

Для отката переключите `current` на предыдущий каталог `release-*`. Для остановки обновлений: `systemctl disable --now routeva-rules-update.timer`. Остановка таймера сохраняет опубликованные файлы.

## AmneziaVPN: совместимый импорт

`/routing/amnezia-ru-direct.json` — JSON в формате импорта AmneziaVPN 5.1.0.6: массив объектов `hostname`, `ip`, `ips`. Он содержит российские IPv4-подсети и снимок разрешённых IPv4-адресов доменов. Выберите в Amnezia раздельное туннелирование по сайтам/IP → «Адреса из списка не должны идти через VPN» → импорт JSON → добавление к существующему списку. Затем включите раздельное туннелирование и переподключитесь. На Android для MAX полезно дополнительно исключить само приложение: это охватывает его новые и общие CDN-адреса.

Официальная AmneziaVPN на Windows, macOS, Android и iOS пока не подписывается на автоматические обновления этого JSON. URL здесь служит для скачивания свежего файла; его нужно импортировать повторно. Обход этого ограничения для iOS/Android в данном релизе не реализован. Встраивание неизвестных полей в VPN-ключ не включает автообновление. Поддержка запрошена в [amnezia-client#3399](https://github.com/amnezia-vpn/amnezia-client/issues/3399).

IP-маршрутизация Amnezia менее точна, чем доменные правила Routeva: адреса CDN меняются, а один IP может обслуживать несколько сайтов. Импорт сохраняет режим остальных маршрутов и не изменяет криптографические ключи. Системный VPN, включая Happ, также должен разрешать прямые маршруты: браузерный `DIRECT` сам по себе не обходит системный TUN.
